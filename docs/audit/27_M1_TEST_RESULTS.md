## Runtime

A preliminary smoke launch used the older 2026-09-23 local `AnomalyDX11.exe` in an isolated `gamma-runtime/m1-pre-final/bin` directory. With `-dedicated -netcoop -fsltx fsgame_server.ltx`, the process stayed alive but stopped responding before a non-empty log or gameplay-ready signal; a second attempt with `-nosplashwindow` behaved similarly. Both test processes were stopped. This older binary is not evidence for the final M1 commit.

The matching `316db1a3f` DX11 CI artifact (`SHA-256 E8B5F2B7F1CFF69F9E391246BF115CCAC87127FF2C90FAE42AEE2DB02C37D616`) was launched three times against the isolated GAMMA runtime, including an attempt without `-dbg`. Every attempt exited with Windows exception `0xC0000005`; the log was zero bytes and no server port was ready. Windows Error Reporting gave executable RVA `0x1ff582`. The exact CI PDB maps that address to `CScriptStorage::print_stack` at `src/xrServerEntities/script_storage.cpp:607`; disassembly shows a read through an invalid `this` pointer. Source review found `CAI_Space::init` skipped Lua creation on a dedicated server.

The matching `10df37c24` DX11 CI executable (`SHA-256 0C23B5F4FB8FFDCC6F077A2E4BDEBDB2DB4A33C46656BD78B0DBDF86A20D510F`) passed the previous Lua fault and loaded the GAMMA scripts. Its server process then opened an `Unhandled exception occured` dialog before binding port 1267. The 219,834-byte log ended with address `0x140D117EE`; the exact CI PDB maps RVA `0xD117EE` to `dxUIRender::SetShader` at `src/Layers/xrRender/dxUIRender.cpp:30`. Source call flow showed that `CApplication::LoadDraw` called `Console->OnRender` on dedicated, which attempted to use a missing UI shader. Commit `38cd3aedb` skips that loading UI path. No movement case has been marked passed.

The matching `38cd3aedb` DX11 CI executable (`SHA-256 3324532AACF39B8F08C0E134F45AB54ACF143B89CE9E729542DC894B6AE6964B`) still raised `0xC0000005` before binding port 1267. WER recorded RVA `0xD117CE`, again `dxUIRender::SetShader:30` in its exact PDB. An attached DbgEng debugger captured the first-chance exception stack: `dxUIRender::SetShader → CConsole::DrawBackgrounds → CConsole::OnRender → CRenderDevice::on_idle → CRenderDevice::Run → Startup`. This showed a second render path through `seqRender`, independent of `LoadDraw`. Commit `4afc4c177` prevents dedicated console registration in that callback and guards `OnRender`.

Local runtime revisions then passed successive startup stages. `4afc4c177` reached GAMMA Lua and crashed in a dedicated font getter. After that font fix, an uncommitted local build reached ALife reload and crashed on absent task/map UI managers. `c40b96714` created the game and accepted a localhost client before crashing on a missing Actor AI location; `1d116f245` reached map manager use; `84b008049` reached inventory spawn before PDA accessed its HUD; `95430db18` reached the Actor schedule before condition boosters accessed the HUD; `217a72e7d` reached PDA contact detection before its UI animation. Every crash was mapped through the matching local PDB and corrected in the cited source path.

The local full-solution `3bc288e7c` DX11 executable (`SHA-256 9244C6C2C9CCB9281A56FC95E654A9FF0324BF8EA499EA00D9D4289B4BE5E1A9`) ran with `-dedicated -netcoop` and the prepared GAMMA runtime. GAMMA script warnings concerning `sim_squad_scripted`/`level_vertex_id`, duplicate story IDs, missing spawn sections and `fake_start/level.hom` remain in the log. They were not treated as movement test passes or silently fixed in the source modpack.
